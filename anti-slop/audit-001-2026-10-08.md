# antislop audit 001

Date: 2026-10-08
Project: note.local (Next.js 15 notes app, `src/`)
Mode: AFTER (audit only, nothing modified)
Scope: core filter + `antislop-ui`, `antislop-human`, `antislop-layoutmobile`, `antislop-copywriting`, `antislop-code`
Verification: contrast measured with `.opencode/skills/antislop-human/contrast-check.py`; app not run (`node_modules` absent), so findings marked *(unrun)* were checked by code inspection only.

Priority follows rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## Findings

### HIGH (Hard Gate)

1. **R-03** — `src/components/Sidebar.tsx:20` the sidebar is `hidden ... md:block`, so below 768px there is no navigation at all: labels, Archive and Trash are unreachable on a phone, and there is no bottom nav or menu to replace it.
2. **R-03** — Tap targets are far under 44px: color dots are `h-5 w-5` = 20px (`ColorPicker.tsx:14`), note action buttons are `p-1 text-sm` ≈ 28px (`NoteCard.tsx:13`), native checkboxes ≈ 16px, sidebar rows ≈ 36px (`Sidebar.tsx:17`).
3. **R-25** — `text-neutral-500` (#737373) fails WCAG AA on both surfaces: **4.18:1** on the page background (#0a0a0a) and **3.78:1** on note cards (#171717), measured with the contrast script. Hits "No notes" (`NotesApp.tsx:76`), "Pinned"/"Others" headings (`NotesApp.tsx:77,79`), all `placeholder:text-neutral-500`, completed checklist text (`NoteCard.tsx:33`, `ChecklistEditor.tsx:18`), and the ✕ remove button (`ChecklistEditor.tsx:20`).
4. **R-32** — `outline-none` on inputs with no replacement focus style: `Composer.tsx:44,52`, `NoteEditor.tsx:35,42,64`, `ChecklistEditor.tsx:18,32`, `NotesApp.tsx:68`. Keyboard users lose the focus indicator; the search field only shifts to a 60%-alpha border.
5. **R-32** — A note opens from `onClick` on a plain `<div>` (`NoteCard.tsx:23`): no `tabindex`, no role, no Enter/Space handler, so notes cannot be opened keyboard-only.
6. **R-32** — `NoteEditor` (`NoteEditor.tsx:17`) is not a dialog: no `role="dialog"`, no `aria-modal`, no focus trap, so Tab walks into the page behind the overlay. Escape does close it, which is the part that passes.
7. **R-27** — No loading state: the first fetch renders "No notes" (`NotesApp.tsx:76`) before data arrives, so loading and empty read as the same screen.
8. **R-27** — No error state: every API failure goes to `console.error` (`NotesApp.tsx:24`) and the UI silently shows an empty list, indistinguishable from a real empty state.
9. **R-27** — The empty state is the bare words "No notes": no cause, no next action, and the same line for first run, zero search results, and an empty label filter.
10. **R-37** — No `DESIGN.md` and no direction of any kind; the work is not labeled *"draft without direction"*, and the dials ENERGY / RHYTHM / MOTION are never declared.
11. **R-35** — The app has never been verified: no `node_modules`, no build, no recorded click-through. Mobile overflow, tab order, and every control listed above are unproven *(/unrun)*.

### MEDIUM (Purpose-Gate)

12. **R-04** — Emoji is the icon system: 💡 🏷 🗑 in `Sidebar.tsx`, 📌 🗄 🗑 ♻ ✕ in `NoteCard.tsx`, 📌 ☑ ≡ in `Composer.tsx`, ✕ in `ChecklistEditor.tsx`, none with a written relevance to what it labels.
13. **R-06** — "Pinned"/"Others" use uppercase with wide tracking (`NotesApp.tsx:77,79`) and the typeface is the untouched default system stack with no brand-character reason written down.
14. **C-4** *(no R-XX; craft/accessibility)* — `lang="id"` (`layout.tsx:9`) while every visible string is English, so screen readers pronounce English with Indonesian phonetics; pick one language for the UI.

### LOW (Quality Locks)

15. **R-31** — No decision is written down anywhere: no design doc, no rationale for palette, layout, type, or spacing, so the purpose test has nothing to check against.
16. **R-21** — Dark is forced by the hardcoded `<html className="dark">` (`layout.tsx:9`) with no stated reason and no toggle, leaving the light styles in `globals.css:5` unreachable dead code; `color-scheme: light dark` on `:root` still follows the OS, so native controls can disagree with the page.
17. **R-30** — The whole app reads as a Google Keep clone (rounded-r-full sidebar pills, masonry of colored cards) with no reference on record. If that is the intent, say so and this finding closes.

## Checks that passed

- **R-02** no em dash anywhere in `src/`.
- **R-17 / R-18 / R-36 / R-38** no statistics, testimonials, or fabricated claims of any kind.
- **R-23** no invented assets: no logo, avatar, or image was generated; the title is plain text.
- **R-24 / R-26** every nav item and control is wired to real behavior: no dead buttons found, sidebar views, pin/archive/trash, restore, empty trash, color picker, checklist edit, label add/remove, search and create all reach real handlers.
- **R-10 / R-13 / R-19** blur appears on 2 elements (at the cap), no glow, no template animation or endless loop.
- **R-15 / R-16** no generic CTAs and no marketing buzzwords; copy is short and plain.
- **R-11 / R-14** radius is mixed deliberately (cards, pills, dots, rounded-r-full nav) and cards are content-driven, not template copies.
- **antislop-code** the only two comments in the codebase are one-liners that carry real information (`notes/route.ts:19`, `lib/util.ts:5`); no AI comment slop.
